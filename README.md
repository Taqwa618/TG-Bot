# 🤖 Telegram-бот обратной связи

Простой и полностью рабочий бот, который принимает обращения от пользователей
и пересылает их администраторам, а ответы администраторов доставляет обратно
пользователям.

Написан на **Python + aiogram 3** (актуальная асинхронная библиотека для
Telegram-ботов). Данные хранятся в базе **SQLite** — файл `feedback.db`
создаётся сам при первом запуске.

---

## 1. Что умеет бот

**Для пользователей:**

| Возможность | Как пользоваться |
|---|---|
| Отправить обращение | Кнопка **«📝 Написать обращение»**, затем одно сообщение: текст, фото, видео, видео-заметка, голосовое, аудио, документ или стикер |
| Узнать свой ID | Кнопка **«🆔 Мой ID»** или команда `/id` |
| Помощь | Кнопка **«ℹ️ Помощь»** |
| Отменить отправку | `/cancel` |

**Для администраторов:**

| Возможность | Как пользоваться |
|---|---|
| Получать обращения | Копия каждого обращения приходит админам автоматически (со кнопками) |
| Ответить — способ 1 | Кнопка **«✉️ Ответить»** под обращением → написать ответ |
| Ответить — способ 2 | Ответить (**Reply**) на копию обращения — текстом, фото, файлом и т.д. |
| Ответить — способ 3 | `/reply <номер обращения> <текст>`, например `/reply 3 Ваш вопрос решён` |
| Статистика | `/stats` или `/admin` |
| Список пользователей | `/users` (последние 10) |
| Карточка пользователя | `/find <user_id>` — данные + последние 5 обращений |
| Заблокировать спамера | `/ban <user_id>` или кнопка **«🚫 Забанить»** под обращением |
| Разблокировать | `/unban <user_id>` или кнопка **«✅ Разбанить»** |
| Узнать ID чата | `/id` |
| Выбраться из режима ответа | `/cancel` |

**Дополнительно:**

- **Антифлуд** — пользователь не может отправлять обращения чаще, чем раз в
  `FLOOD_LIMIT_SECONDS` секунд (настраивается в `.env`).
- **База данных** — пользователи, обращения и статусы сохраняются в SQLite;
  данные не теряются при перезапуске.
- **Логи** — всё пишется в файл `logs/bot.log` и в консоль.
- **Несколько админов** — обращения получают все, кого вы указали в `ADMIN_IDS`
  (личные чаты и/или группа).

## 3. Установка

### Шаг 1. Python

Нужен **Python 3.10 или новее**: <https://www.python.org/downloads/>
При установке на Windows обязательно поставьте галочку
**«Add python.exe to PATH»**.

Проверка:

```bash
python --version
```

### Шаг 2. Зависимости

Откройте терминал в папке проекта и выполните:

```bash
pip install -r requirements.txt
```

### Шаг 3. Создайте бота в Telegram

1. Откройте [@BotFather](https://t.me/BotFather).
2. Отправьте `/newbot`, придумайте имя и username (username заканчивается на `bot`).
3. BotFather пришлёт **токен** вида `1234567890:AA...` — он понадобится на шаге 4.

### Шаг 4. Узнайте свой ID (ID администратора)

1. Откройте [@userinfobot](https://t.me/userinfobot) — он сразу покажет ваш **Id**.
2. (Или позже отправьте своему боту команду `/id` — бот сам покажет ID.)

### Шаг 5. Настройте файл `.env`

В папке проекта есть шаблон `.env.example`:

1. Скопируйте его и переименуйте копию в **`.env`**
   (Windows: создать текстовый файл `.env` — точка в начале имени обязательна).
2. Заполните:

```ini
BOT_TOKEN=1234567890:AA...      # токен от BotFather
ADMIN_IDS=123456789             # ваш ID (несколько админов — через запятую)
FLOOD_LIMIT_SECONDS=10          # пауза между обращениями, сек
```

### Шаг 6. Запуск

**Windows** — просто двойной клик по `run.bat`,
или в терминале: `python bot.py`

**Linux / macOS:**

```bash
python3 bot.py
```

Если всё настроено верно, в консоли появится строка
`Бот запускается. Администраторы: [...]` — бот работает.
Остановка: `Ctrl+C`.

> ⚠️ Бот получает сообщения, только пока запущен. Для работы 24/7
> запустите его на сервере (см. раздел 9).

## 4. Первый запуск — проверка

1. Откройте чат с вашим ботом, нажмите **Start**.
2. Нажмите **«📝 Написать обращение»** и отправьте тестовое сообщение.
   Так как вы сами админ, копия придёт вам же — удобно для проверки.
3. Ответьте на копию (Reply) текстом — ответ придёт вам же в чат с ботом.

| `bot.py` | Весь бот: хендлеры, клавиатуры, тексты, запуск. В начале файла — обзор логики |

## 6. Как устроен код (коротко, для доработки)

- **`bot.py`**
  - `router` — объект, к которому «приклеены» все хендлеры.
  - **Порядок регистрации хендлеров важен**: aiogram проверяет их сверху вниз
    и вызывает первый подходящий. Команды → инлайн-кнопки → режимы FSM →
    приём обращения → общая подсказка в самом конце.
  - `UserStates` / `AdminStates` — «состояния» (FSM): бот помнит, что
    пользователь сейчас пишет обращение, а админ — ответ.
  - `IsAdmin` — фильтр, который пропускает только админов из `config.ADMIN_IDS`.
  - `extract_content()` — определяет тип сообщения (текст/фото/…).
  - `deliver_answer()` — доставка ответа пользователю, учитывает случай,
    когда пользователь заблокировал бота.
- **`storage.py`** — три таблицы:
  - `users` — ID, имя, username, счётчик обращений, флаг бана;
  - `tickets` — обращения: номер, тип, текст, статус (`new`/`answered`);
  - `ticket_copies` — связывает «копию обращения в чате админа» с номером
    обращения. Благодаря этой таблице Reply-ответ админа попадает
    нужному пользователю.
- **`config.py`** — читает `.env` один раз при старте; если токена или админов
  нет, бот останавливается с понятной подсказкой.

## 7. Частые вопросы и проблемы

**Бот не отвечает.**
Проверьте: токен в `.env` верный; бот запущен (окно консоли открыто);
вы нажали **Start** в чате с ботом — Telegram не даёт боту писать первым,
пока пользователь не нажал Start.

**«Не удалось отправить обращение админу …»** в логах.
Админ не нажал Start у бота. Откройте чат с ботом и нажмите Start.

**«Ответ не доставлен…»**
Пользователь заблокировал бота или никогда не нажимал Start.

**Хочу, чтобы обращения приходили в группу.**
Добавьте бота в группу, дайте ей права (хотя бы чтение сообщений),
запустите `/id` в группе — ID группы отрицательный (например, `-1001234...`).
Впишите его в `ADMIN_IDS` через запятую: `ADMIN_IDS=111111, -10022222`.

**Как отключить антифлуд?**
Поставьте `FLOOD_LIMIT_SECONDS=0` в `.env`.

**Где посмотреть, кто и что отправлял?**
Откройте `feedback.db` программой [DB Browser for SQLite](https://sqlitebrowser.org/)
или командой `/users` и `/find` в боте.

**Хочу сбросить все данные.**
Остановите бота и удалите файл `feedback.db` — он создастся заново.

## 8. Безопасность и ограничения

- Токен бота — это пароль: не публикуйте его и не коммитьте `.env` в git.
- База SQLite хранится рядом с ботом — регулярно делайте её копию
  (просто файл `feedback.db`).
- Синхронный `sqlite3` подходит для небольшой нагрузки (штатный сценарий
  «обратная связь»). Для десятков тысяч одновременных пользователей
  имеет смысл перейти на PostgreSQL/Redis и асинхронный драйвер.
- Обращения пересылаются как копии (`copy_message`), поэтому админ не видит
  username отправителя — приватность соблюдена, а ID всегда есть в базе
  (кнопка «ℹ️ Инфо» или `/find`).

## 9. Запуск на сервере 24/7 (кратко)

На Linux (Ubuntu) с systemd:

```bash
# 1. Скопируйте папку проекта на сервер, установите зависимости
pip3 install -r requirements.txt

# 2. Заполните .env, затем создайте сервис
sudo nano /etc/systemd/system/feedback-bot.service
```

```ini
[Unit]
Description=Telegram feedback bot
After=network.target

[Service]
WorkingDirectory=/opt/feedback_bot
ExecStart=/usr/bin/python3 bot.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now feedback-bot   # запустить и включить автозапуск
journalctl -u feedback-bot -f              # смотреть логи
```
